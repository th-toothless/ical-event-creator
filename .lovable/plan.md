# Plan: Excel → iCal generator web app

A single-page web app, deployable to GitHub Pages, that lets the user upload the rozpis xlsx, pick a person, optionally add a note, and download an `.ics` file with one event per shift.

## How the Excel is read

Each month is a separate sheet named `01`–`12`. In every sheet:
- Row 7 (0-indexed 6) holds day numbers (`1.`, `2.`, …), starting at column 5.
- Row 8 (0-indexed 7) holds the weekday abbreviations.
- Names live in column 36 (header `Podpis`), rows 9 onward.
- The shift code for each (person, day) is the cell at that name's row and the day's column.

The year is taken from the date cell at column 1, row 5 of each sheet (e.g. `2026-01-01`).

## Shift code mapping

Codes are matched case-insensitively, with leading prefix letters (T, C, S…) stripped so variants like `Cd`, `Tcd`, `Tn`, `Cn` all map correctly. Only these codes become events:

| Code | Start  | End                    | Title |
|------|--------|------------------------|-------|
| CD   | 07:00  | 07:00 next day         | Služba 24h (CD) |
| D    | 07:00  | 19:00 same day         | Denní (D) |
| N    | 19:00  | 07:00 next day         | Noční (N) |
| G    | 07:00  | 17:00 same day         | Garáž (G) |

Everything else (`v`, `pn`, `xxx`, `e`, `sr`, `m`, blanks…) is ignored.

## UI

One page, in Czech:
1. File picker for the `.xlsx`.
2. Dropdown of people (auto-populated from column 36, blanks/numeric rows filtered out).
3. Optional **Poznámka** textarea — appended to the `DESCRIPTION` of every generated event.
4. **Stáhnout .ics** button → downloads `rozpis-<jmeno>-<rok>.ics`.

## Tech / deployment

- Plain static site (no backend): `index.html` + one JS bundle, parsing handled in-browser by `xlsx` (SheetJS) from a CDN.
- iCal generated by hand (small, standard VCALENDAR/VEVENT writer) — no extra dependency.
- Ships as a separate folder so it can be pushed to GitHub and served by GitHub Pages with zero config.

## Build location

This Lovable project uses TanStack Start (not a pure static site), so I'll put the generator in `public/ical/` as plain `index.html` + `app.js`, reachable at `/ical/` on the preview URL and copy-pasteable into any GitHub Pages repo. The main app's routes stay untouched.

## Open questions

1. **CD on the last day of the month** — should the event still end 07:00 of the 1st of the next month (crossing into the next sheet)? Default: yes.
2. **Timezone** — default to `Europe/Prague`. OK?
3. Should the **note** also go into the event title, or only the description? Default: description only.
